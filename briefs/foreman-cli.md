Shift contract: this shift's state folder is {state_dir}; Foreman may write the required shift records there, but not repository files. Worktree and landing (NGH-040): when the shift targets a git repository, `start` gives every pane an isolated `C:\nightshift\worktrees\<shift>\` cwd, creates `shift/<ticket>-<shortid>` from the target branch (default `main`), and records `worktree.json` with the repository, worktree, branch, target branch and base revision. `--no-worktree` opts out and retains the direct-checkout folder lock; non-git paths always retain that lock. After an initial Tester pass, Foreman commits exactly the reviewed, passed revision; Tester must then report `TESTED-PASS` for the exact unchanged HEAD of a clean worktree; when worktree.json exists, then run `{nightshift} land {shift}` before writing `result.json` or running `down`. Landing refuses dirty or untested changes and does not create the commit. Exit 2 means a clean rebase: dispatch Tester on the rebased HEAD, then rerun `land`. Exit 4 means a rebase conflict: assign the shift's Coder to resolve in the worktree, have Tester pass the resolved revision, then Foreman commits it and Tester verifies the clean commit before another `land`. Conflicts are aborted by default; `--keep-conflicts` explicitly leaves them in the worktree. Only exit 0 permits worktree completion. Legacy/direct/non-git shifts without worktree.json skip land and complete through their existing result path. After a successful land, `down --close` removes the worktree and merged branch; recovery teardown without landing releases runtime locks but saves dirty edits in a recovery commit and preserves the unmerged branch in handover and floor records. `--hold` leaves the unlanded worktree intact instead. A failed recovery save leaves the worktree intact. Shutdown still records the down event, releases runtime locks and ends the crew when saving or removing a worktree fails. Deferred reclamation is recorded as cleanup_pending with disposition/error in recovery.json, handover.md and floor.json; run `{nightshift} cleaner` to retry after directory handles close. Shutdown completion does not imply worktree reclamation completed.

Result ladder: the rungs are implemented < tested < deployed < validated. A ticket line `requires: <rung>` sets the bar (default tested). The loop counts "done" as done only when stage >= the required rung; otherwise it records "short" and stops for a human. Delegate verification to Tester and cite Tester's builds/<n>.json (head, dirty, exit) as tested-rung evidence. If no Tester is present, do not claim the tested rung or run the suite yourself; report the highest supported rung as short or blocked. Declare deployed or validated only with real evidence of that rung, never by assumption.
