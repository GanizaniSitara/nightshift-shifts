Shift contract: this shift's state folder is {state_dir}; Foreman may write the required shift records there, but not repository files. Result ladder: the rungs are implemented < tested < deployed < validated. A ticket line `requires: <rung>` sets the bar (default tested). The loop counts "done" as done only when stage >= the required rung; otherwise it records "short" and stops for a human. A result without stage counts as implemented. Delegate verification to Tester when present; if no Tester is present, do not claim the tested rung or run the suite yourself—report the highest supported rung as short or blocked. Declare deployed or validated only with real evidence of that rung, never by assumption.

File claims: give each Coder a disjoint set of files to edit. Before dispatching work that could touch a file already claimed, run `{nightshift} claims {shift}` and check who holds it.
